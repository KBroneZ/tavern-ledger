## How things work now (lessons from round 4, add to 047's)

- **`gh` is logged in** on this PC (KBroneZ, keyring). Open PRs with `gh pr create`, wait with `gh pr checks <n> --watch`, merge with `gh pr merge <n> --squash`. **Never delete a branch before `gh pr view <n> --json state` says `MERGED`** (round 4 lost a PR that way; restore with `git push origin <sha>:refs/heads/<branch>` and `gh pr reopen`). The local branch delete fails while a worktree uses it: remove the worktree first.
- **Network to GitHub drops now and then:** retry `git fetch`/`pull`/`push` a few times before worrying.
- **Rebuilding the user's app:** only when `Hearthstone` is not running; otherwise start a background loop that waits for it to close, then `Stop-Process -Name desktop`, `cargo build --release --locked -p desktop -p tracker`, `git checkout -- crates/desktop/gen/schemas`, `Start-Process target\release\desktop.exe`. Reparse (`tavern-watch --reparse`, backup `games.jsonl.bak-<session>` first) only when `PARSER_REVISION` changes. Current: parser revision 6, validator 6.
- **Never let a test build show its overlay over the user's game** (sessions 056 and 058 did). Since 059, debug builds and dev-flag runs hide the overlay while Hearthstone runs; keep telling sessions to check before any visual test, and prefer headless renders.
- **Memory reading (D-063, D-069):** the app reads the lobby tribes and the player's own rating, read-only, off by default, never uploaded. Auto mode blocks sessions from running memory tools; the user runs them with `!` in the session's tab (or the hub's), on the screen the session names. Ask the user in plain words and give the exact command.
- **Close finished task tabs** yourself once a session is merged and done: find the `claude.exe` with the session's prompt name in its command line, kill its parent `pwsh -NoExit` tree; then remove the worktree, the local and remote branch, and the folder.
- **Sessions message the hub by name** (`ListAgents`, the `[ref]` suffix is needed); messages to a busy session arrive later. Relay the user's screenshots to sessions as a path in the hub's `images` folder plus a description.
- **Website deploys on merge** (Cloudflare Pages) and Supabase migrations and functions deploy on merge too (D-031): after a merge that touches `supabase/`, check `/auth/v1/settings` still says `disable_signup: true`, functions answer `401` without a token, and the validator answers its version. A migration is R2; one that changes RLS or exposes data is reviewed with `/security-review` and a second AI before merging.
