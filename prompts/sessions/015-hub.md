## How to launch a session

Use the `switch-account` skill (script `open-session.ps1`) with every option given, so it does not need to ask:

- `-Account auto` (it picks the least used of the user's accounts and stops if all are capped: report the reset time, don't work around it).
- `-Model` and `-Effort` from the prompt's header; `-RemoteControl -SessionName "NNN <name>"` and `-Title "NNN <name>"` (the script wants both to start with a letter or digit, so no `#`; the conversation title inside the session keeps `#NNN`).
- `-Worktree NNN-slug`: creates `C:\Users\andia\tavern-ledger\.claude\worktrees\NNN-slug` from `origin/main` (ignored by git). The task session works only there.
- `-InitialPrompt "Read prompts/sessions/NNN-slug.md and act on it. Do not stop. I write in Spanish, you answer in English."`
- If it exits with code 4 (folder not trusted), tell the user and wait for their OK before `-TrustDirectory`.

The prompt file must be on `origin/main` before launching (the worktree is created from it).

1. **State.** `git fetch --prune`; open PRs, CI on `main`, `git worktree list`, running sessions (`Get-CimInstance Win32_Process -Filter "Name='claude.exe'"`, by command line), the plan's task statuses, the desktop app (`Get-Process desktop`, from which folder) and the game count in `%APPDATA%\TavernLedger\games.jsonl` per session, without names.
2. **Launch** what is ready and doesn't overlap.
3. **Watch** without polling fast: check every 20–30 minutes (or when the user asks). A session is finished when its PR is merged and `main` CI is green. If a session seems stuck (no commits or PR for a long time), look at its worktree (`git log`, `git status`) and tell the user; don't take over its work.
4. **Close.** For each finished session: `main` pulled in the main checkout; its worktree removed if clean and its branch merged (`git worktree remove`), the local branch deleted. Never remove a worktree with uncommitted changes or one a running program uses (the desktop app may run from one: move it to a `main` build first, `cargo build --release -p desktop` in the main checkout, then stop the old one and start the new one with `Start-Process`).
5. **Report** to the user in a few lines: what finished, what is running, what waits for them.
6. **Next prompts**: when the queue runs low, write the next ones (`prompts/sessions/NNN-slug.md`, same structure as the recent ones: header with model and effort, working rules, red line, phases, start, task, out of scope, acceptance criteria) and merge them through a PR.
