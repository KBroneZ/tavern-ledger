# Card names, card art and hero portraits: sources and terms (T-304)

Session 026, 2026-10-10. Question: where can the app get card names, card art and hero portraits for the overlay boards, the recap and the hero names, and under what terms? Primary pages read on 2026-10-10 unless noted. No image was downloaded for this research; the only requests were `HEAD` requests to check sizes and headers, and one download of `cards.json` to measure its compressed size (discarded, not saved).

## Today

The log names heroes only (`[entityName=… cardId=…]`, D-017), so the app shows hero names from the player's own log and minions as card ids with attack/health (`BG_CFM_315 3/2`). Nothing is downloaded.

## Blizzard's terms for fan use of its art

Blizzard has **no document called "Fan Content Policy"** (unlike Riot or Wizards of the Coast). The rules that apply are spread over three pages:

- [Legal FAQ](https://www.blizzard.com/en-us/legal/28d5ebbf-c245-4408-8ba9-043dd5f056bf/legal-faq): fan sites may use Blizzard images "within certain limits"; Blizzard grants "a personal, non-exclusive, non-transferable and non-assignable license to use and display, for home, noncommercial and personal use only"; "You must include all copyright, trademark and other notices as appropriate"; Blizzard "reserves the right to revoke this limited use license at any time, for any reason". Nothing on donations, ads or paid features.
- [Trademark usage guidelines](https://www.blizzard.com/legal/38fd0408-8431-469a-99bc-2cd9eb9462c8/blizzard-entertainment-logo-and-trademark-guidelines): marks "only for non-commercial purposes, except as permitted by the applicable Activity Policy" (fan site, community eSports and custom maps policies); credit lines for the marks used; consent "may be withdrawn ... at any time".
- [Terms of use for Blizzard's websites](https://www.blizzard.com/en-us/legal/29232b30-6ae1-4d74-b1c5-8bd1df9e0b63/terms-of-use-for-blizzards-websites): "personal use only", excluding "any commercial use of the Site or the Materials therein" and "downloading (other than the page caching)". So Blizzard's own card library website is not a source for an app.

What this means for us:

- **Images only in free features** (D-003): the overlay, the recap and the history are free and stay free. Never in a paid extra, never next to an ad (there are none), never used in marketing.
- Keep the notice "Unofficial fan project. Not affiliated with or endorsed by Blizzard Entertainment." and add a credit line wherever art shows: "Card art and card data © Blizzard Entertainment."
- No Blizzard logo, and no art in the app's brand or icon (CLAUDE.md rule 5).
- The licence is revocable: the app must work with images switched off or missing (fall back to the card id).
- The art is game content; the app never takes it from the game's files (D-004). It comes from a third party that publishes it (below).

## Sources

### A. HearthstoneJSON (HearthSim)

- **Card data**: `https://api.hearthstonejson.com/v1/latest/enUS/cards.json` ([docs](https://hearthstonejson.com/docs/cards.html)); also per build (`/v1/<build>/…`) and per locale. All cards, Battlegrounds ones included (ids `BG_…`, `TB_BaconShop_HERO_…`, golden `TB_BaconUps_…`). Size: 9.9 MB, **1.6 MB with gzip** (measured). Headers: `cache-control: public, max-age=60`, an `etag`, served by Cloudflare.
- **Art** ([docs](https://hearthstonejson.com/docs/images.html)): `https://art.hearthstonejson.com/v1/256x/<CARD_ID>.jpg` (or `.webp`), 256×256 square art; `512x/`, `orig/` (PNG), `tiles/` (256×59 strips, PNG/JPG/WebP) and full card renders `render/latest/<locale>/256x/<id>.png` (~150 KB). Checked with `HEAD`: a Battlegrounds minion (`BG_CFM_315`) is 9 KB as 256x JPG, 7 KB as WebP, 26 KB as a tile; a hero (`TB_BaconShop_HERO_01`) 16 KB. `cache-control: public, max-age=3600`.
- **Terms**: "You are free to use this API without restrictions"; "avoid direct embedding on high-traffic websites, and instead re-host the images"; commercial use: contact `contact@hearthsim.net`. The site is CC0, but "The JSON files contain data that is Copyright © Blizzard Entertainment - All Rights Reserved". No rate limit or attribution rule published; `robots.txt` allows everything.
- **Account, key, cost**: none.
- **Fit**: a desktop app fetching one data file and a few dozen small images per player is the light use the docs ask for (not a high-traffic website). Fetched at run time and cached on the player's PC, never in the repo (D-017).
- **Risk**: run by a community group (HearthSim); if it stops or changes, images and names disappear until we switch source. Fallback to card ids keeps the app working. The data is generated by HearthSim from the game's files; we never touch those files ourselves.
- Used the same way by several MIT trackers in the survey (bgtracker, openbg, hsbg-overlay; [github-landscape.md](github-landscape.md)).

### B. Blizzard Hearthstone Game Data API (Battle.net developer portal)

- Card search with `gameMode=battlegrounds`, card names, image URLs on Blizzard's CDN, hero data ([docs](https://community.developer.battle.net/documentation/hearthstone/game-data-apis), page needs JavaScript; endpoints known from earlier work). Needs an OAuth **client id and secret** from a Battle.net developer account.
- [Developer API terms](https://www.blizzard.com/en-us/legal/a2989b50-5f16-43b1-abec-2ae17cc09dd6/blizzard-developer-api-terms-of-use): "'Premium' versions of Applications offering additional for-pay features are not permitted"; "You must implement a maximum 30-day TTL ... for all Data obtained through our APIs"; 36,000 calls per hour; "You shall keep Your API Key confidential"; "clearly and conspicuously identify Blizzard ... as the source of the Data"; Blizzard may stop the API at any time.
- **Fit: poor.** The premium clause clashes with D-003's optional paid extras (the same reason Battle.net login was ruled out, D-020). A secret cannot ship inside an open-source desktop app (D-002), so either each player registers their own developer client or we run a proxy (a server, a secret and the 30-day TTL to manage). It is the most "official" source, but costs an account, a secret and the premium conflict.

### C. Names only, no images

- Card names from HearthstoneJSON's `cards.json` (A), no art at all. Lowest risk: no art on screen, so the Fan Content question is only about game text. Less useful: the player still reads text, not pictures.

### Ruled out

- **Blizzard's card library website** (`hearthstone.blizzard.com`): website terms are personal use only and forbid downloading other than page caching.
- **Hearthstone Wiki** (wiki.gg): text CC BY-NC-SA; the art belongs to Blizzard and the wiki grants nothing on it; image hotlinking to a wiki is impolite.
- **Firestone / Zero to Heroes CDN, HSReplay, HDT resources**: no licence, or "All Rights Reserved", and CLAUDE.md rule 1. Not used.
- **The game's own files** (extracting textures or `CardDefs`): red line (D-004, D-006).

## Comparison

| | A. HearthstoneJSON | B. Blizzard API | C. Names only |
|---|---|---|---|
| Names | yes | yes | yes |
| Art and hero portraits | yes (256x, tiles) | yes | no |
| Account or secret | none | developer account, client secret | none |
| Cost | free | free | free |
| Paid extras (D-003) | art only in free features; ask HearthSim before any paid extra uses it | premium apps not allowed at all | n/a |
| Caching | allowed; local cache | 30-day TTL | local cache |
| Requests | 1 data file (1.6 MB gz) per game build, images on demand | OAuth + paged searches | 1 data file |
| Risk if it goes | fallback to ids | fallback to ids | fallback to ids |

## Recommendation

**A, HearthstoneJSON**, with these limits (to be recorded as D-038 if the user agrees):

1. Data: one `cards.json` (enUS) fetched with gzip, kept on the PC and refreshed only when the game build in the log is newer than the cached one, or after 7 days; conditional requests with the `etag`.
2. Art: `256x` JPG for hero portraits and board minions, fetched only when a card is about to be shown, cached on the PC with a size cap (50 MB, oldest dropped first), a few requests at a time.
3. Every request: timeout, identifiable User-Agent (`TavernLedger/<version> (+https://tavernledger.net)`), response validated (JSON shape; image magic bytes, type and size limits). Any failure shows the card id and "unknown", never a guessed or wrong picture.
4. Nothing is committed: no card data, no images, no fixtures with real data (tests use synthetic JSON and tiny made-up bytes).
5. Art only in free features; a credit line "Card art and card data © Blizzard Entertainment" next to the existing notice; a setting to switch images off.
6. Before any paid extra ships, ask HearthSim (`contact@hearthsim.net`) and recheck Blizzard's terms.
