## Lessons from round 3 (add to 036's list)

- **Conflicts:** `git merge-tree --write-tree --name-only origin/main origin/<branch>` and look for `CONFLICT` lines; the first line (a tree id) alone says nothing. GitHub does not run CI on a conflicting PR (only "Supabase Preview skipping" shows): check `gh pr view <n> --json mergeable` before waiting. Two sessions that both append rows to `DECISIONS.md` or `plan.md` conflict; ask the later one to merge `origin/main` and keep both rows in number order.
- **Line endings:** the checkout has `core.autocrlf=true`, so working files are CRLF while the index is LF. Check the index: `git ls-files --eol <file>` (`i/lf`), or in Git Bash with `export MSYS_NO_PATHCONV=1` first, `git cat-file blob origin/<branch>:<file> | tr -cd '\r' | wc -c` (0 = fine). Without `MSYS_NO_PATHCONV`, Git Bash mangles `branch:path` and the check fails silently. When the hub edits a doc in a worktree, keep the working file's endings (read, edit, write back as found).
- **CI does not build `crates/desktop`** and does not run its Node UI tests. After merging a PR that touches `crates/desktop`, the rebuild of the user's app is the build check.
- **gitleaks scans the full history:** a made-up test value that looks random fails CI even after it is changed. Fix: change it to an obviously fake, low-entropy value, and add the old fingerprints from the CI log to `.gitleaksignore` with a comment (as #013, #016, #72 did).
- **`gh`** is logged in on this machine for KBroneZ (keyring) and works in the hub. Task sessions still hand their branch to the hub.
- **Dashboards:** use **Claude in Chrome** (the user's Chrome, already signed in to Supabase and Cloudflare). The built-in browser is not signed in, and Claude never signs in. Each dashboard save needs the user's OK for that change. Done this way on 2026-10-10: Supabase "Write audit logs to the database" on; Cloudflare `dmarc@tavernledger.net` forwarding plus the `_dmarc` `rua`; Supabase legacy JWT-based API keys **disabled** (the same page now shows "Re-enable JWT-based API keys" for a rollback).
- **Worktree folders** cannot be deleted while a session's tab is open (Windows says "Permission denied"). `git worktree remove` still unregisters them; delete the empty folders once the user has closed the tabs.
